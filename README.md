# find-prospects · 找客户，每批5家

一个用于 Codex 的跨行业企业客户搜寻技能。从公司名称或官网出发，先研究供方业务、交付能力和买方场景，再寻找有公开证据支持的潜在企业客户。

## 使用方式

把本仓库作为 `find-prospects` 文件夹放到个人 Codex 技能目录（默认 `~/.codex/skills/`），保持如下结构：

```text
~/.codex/skills/find-prospects/
├── SKILL.md
├── agents/openai.yaml
└── references/batch-template.md
```

也可以在本地执行：

```sh
git clone https://github.com/Leon-lee-L1hanG/find-prospects.git ~/.codex/skills/find-prospects
```

开始任务：

```text
使用 $find-prospects，为【公司名称或官网】寻找5家潜在客户。
先自行研究公司，关键资料不足时向我补问。
```

后续可以说“继续下一批”，或“按这家客户的画像继续寻找”。技能会沿用同一供方已确认的筛选条件和排除记录；换公司时重新研究，不跨公司挪用资料。

## 工作流程

1. 查询公司官网、产品、服务、案例和实际交付范围。
2. 区分供方和样本买方，识别具体购买场景。
3. 公开资料不足以判断关键条件时，每轮补问1–3个具体问题。
4. 查找并核验候选企业的身份、匹配证据、关键规格、地区及公开联系入口。
5. 去除重复企业、老客户、明确拒绝对象和不符合硬条件的对象。
6. 默认每批交付5家，以及独立Markdown、来源链接和针对性的未发送联系草稿。

有现成总台账时，追加并保留用户修改，同时提供易阅读的批次文件。不足5家时如实报告，不编造或降低硬条件凑数。

## 输出包含

- 客户概览、企业名称、角色和地区。
- 具体匹配理由及可核验的来源。
- 关键规格、交付地点、待核事项和商业限制。
- 官网公开邮箱、电话或联系表单及联系人职责说明。
- 建议首先核实的问题和未发送的联系草稿。

## 边界

这是研究工作流技能，需要运行环境提供可用的公开搜索或浏览能力。它不是独立运行的爬虫或自动获客平台，不保证产生询盘和订单。

候选画像匹配不等于买方已表达购买意向。默认不发邮件、不读取私人邮箱、不自动报价、报名、付款或定时外联。实际外部行动需有对应用户授权。

仓库仅包含通用技能与模板，不包含任何客户数据库、业务邮件账号或企业内部资料。
